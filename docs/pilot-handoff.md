# Hermes 自用试用交付 · 2026-10-26

本交付包包含当前已验证的项目源码。默认使用现有 Hermes 模型路由和本地 E5-small；
Qwen、BGE、研究 ANN、Shadow 和机器预标注不会自动启用，也不需要安装研究 Torch。
新模型选型与真实数据正式评测继续等待人工复核，不作为本次试用的安装前提。

## 安装与升级

1. 解压到独立的源码目录，例如 `C:\Tools\hermes-kg-plugin-pilot-2026-10-26`。
   不要解压到 Hermes profile 内，也不要让源码目录包含 profile。
2. 确认 Hermes 已安装并配置模型、Neo4j 可连接；本机需要 Python 3.11+、
   Node.js 22.12+ 的22.x或24.x、npm和uv。首次需要网络下载锁定依赖及E5权重。
   部署命令不会安装或启动 Hermes、Neo4j 本身。
3. 结束目标 Hermes 中正在执行的任务，在解压后的项目根目录运行：

   ```powershell
   python scripts/deploy.py --home "$env:LOCALAPPDATA\hermes"
   ```

   新装和升级使用同一命令。自定义 profile 将 `--home` 改为其实际路径。
   首次按提示输入数据库设置，密码输入隐藏；升级保留连接、namespace、身份、令牌和同步进度。
   部署会构建Web、准备独立运行环境、激活provider并通过官方入口重启目标Hermes网关。
   `ok:true, complete:true` 才表示完整部署通过；不要用 `--skip-*` 作为正常安装。
4. 打开 `http://127.0.0.1:8765`。将目标profile中 `kg-console.token` 的内容粘贴到连接框；
   自定义端口以 `kg.json` 为准。令牌只在本机使用，不需要发送给任何人。

可选的Windows用户登录自启动：在同一命令末尾增加 `--autostart`。
未启用自启动时，电脑重启后可运行 `python '<profile>/scripts/kg_service.py' start`。
已有可验证的自启动设置在升级时保留和迁移。

交付包是源码包，部署仍需构建依赖，不是无前提的离线安装器。Windows已经实测；
macOS/Linux使用实际profile路径（通常 `~/.hermes`），没有把本次检查当作其他系统的实机验收。

## 安装后试用

- 在Hermes中请求调用 `kg_status` 检查连接和provider，然后用 `kg_search` 搜索一条已有记忆。
- 在Web中查看依据、更正一条你愿意修改的记录，再让Hermes显式重新调用 `kg_search` 核对。
  新的查询会读取当前版本；已经生成的回答和旧上下文不会追溯修改。
- 普通聊天产生的新事实先进入同步流程；需要立即处理时在Web运行同步，待审候选须批准后才成为事实。
  首次接入不自动回填全部旧聊天，历史回填需要你明确选择范围。
- 试用时可自行新建一条有明显试用标记的记录，结束后在Web归档，避免与日常知识混淆。

## 升级保护与回退

安装入口不会用交付包覆盖你的 `kg.json`、访问令牌、会话数据库或同步队列。
升级过程生成本地备份与事务记录；普通失败自动恢复原payload和配置。出现未完成事务时，
保留 `<profile>/kg-deploy/` 并按 [部署说明](deployment.md) 恢复，不要直接删除事务记录。
部署结果位于 `<profile>/kg-deploy/last-result.json`；成功后退版使用完整旧源码包执行同一命令。

若旧 `model_cache` 显式指向原源码目录，不要立即删除那个目录。缓存路径会被保留；
需要移动时按部署文档迁移至稳定位置并重新验证模型。交付包不包含个人模型缓存或数据库。
